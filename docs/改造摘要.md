# Element OTel Phase 1b 改造摘要

> 完成时间：2026-09-02  
> 对应标准：《分布式链路追踪标准》v1.5 §6 bssvc-service 改造 Phase 1b

---

## 核心变更

### 1. 新增 `trace` 包能力

| 文件 | 说明 |
|------|------|
| `trace/config.go` | `Config` 结构：`Enabled`、`Exporter`、`ServiceName`、`SampleRate` |
| `trace/provider.go` | `Init()` / `Shutdown()`：注册 TracerProvider + W3C Propagator |
| `trace/sync.go` | `Sync(ctx)`：将 OTel trace/span ID 桥接到 logger 用的 ctx key |
| `trace/trace.go` | `Continue()`：优先读 OTel SpanContext，不再伪造 Remote SpanContext |

### 2. 中间件桥接（去 `X-Trace-Id`）

**GoFrame**
- `bindTrace`：从 `gtrace.GetTraceID` 桥接 → `trace.Sync`
- 依赖 GoFrame 内置 `internalMiddlewareServerTracing`，不再独立解析头

**Gin**
- 新增 `ugin.Tracing(serviceName)`：封装 `otelgin.Middleware`
- 须在 `MiddlewareHeader` 之前注册

**Recover / ExceptionHandler**
- `ensureIDs` 只处理 `X-Req-Id`，trace 由 OTel 负责

### 3. 出站 HTTP（新 Req ID）

| 函数 | 行为 |
|------|------|
| `request.Inject` | inject `traceparent` + **每次新建** `X-Req-Id` |
| `request.Outbound` | 返回 map：`traceparent` + `X-Req-Id` |
| `request.EnsureID` | 仅 HTTP 入站复用 / 生成 request_id |

### 4. `ctx` 包

| 函数 | 变更 |
|------|------|
| `GetTraceId` | 优先读 OTel SpanContext |
| `RunNamed` / `Run` | 创建真实 Root Span（不再只生成 ID） |

## 命名优化

| 旧名 | 新名 | 说明 |
|------|------|------|
| `SyncContextKeys` | `Sync` | 简化桥接函数名 |
| `Config.Sampling` | `SampleRate` | 更清晰 |
| `trimGRPCEndpoint` | `cleanEndpoint` | 更通用 |
| `request.RequestID` | `request.ID` | 简化 |
| `request.EnsureRequestID` | `request.EnsureID` | 简化 |
| `trace.FirstHint` | `trace.First` | 简化 |
| `bg(ctx)` | `safe(ctx)` | 语义更准确 |
| `put(ctx, tid)` | `set(ctx, tid)` | 简化 |

## 配置示例

### 层 1（传播 + 日志，不上报）

```yaml
trace:
  enabled: true
  exporter: none
  service_name: my-service
```

### 层 1 + 层 2（完整上报）

```yaml
trace:
  enabled: true
  exporter: otlp
  endpoint: otel-collector:4317
  service_name: my-service
  sample_rate: 0.1
```
