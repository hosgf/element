# 架构与代码规范

## 异常处理

### 统一使用 `uerrors.BizError`

不再使用：

- `gerror`（GoFrame 错误）
- `ProxyError`（应迁移到 BizError）
- 裸 `error` 直接返回（应包装为 BizError）

### 错误创建

```go
// 系统错误
err := uerrors.NewSystemError("操作失败", "详细描述")

// 业务逻辑错误
err := uerrors.NewBizLogicError(code, "消息", "详细信息")

// 验证错误
err := uerrors.NewValidationError("字段名", "验证消息")

// Kubernetes 错误（自动填充 RequestID）
err := uerrors.WrapKubernetesError(ctx, k8sErr, "操作名称")
```

### 最佳实践

```go
func (o *operation) DoSomething(ctx context.Context) error {
    _, err := o.api.DoSomething(ctx)
    if err != nil {
        return uerrors.WrapKubernetesError(ctx, err, "执行操作")
    }
    return nil
}
```

## Context 使用规范

### 1. 异步操作必须接受 context.Context

```go
// ✅
func (o *operation) List(ctx context.Context, namespace string) ([]Item, error)

// ❌
func (o *operation) List(namespace string) ([]Item, error)
```

### 2. Context 传递

- 第一参数为 `context.Context`
- 从请求入口一路传递到最底层
- 非 HTTP 新执行单元用 `ctx.Run`；goroutine 用 `ctx.Go`

### 3. 读取链路与请求 ID

```go
import "github.com/hosgf/element/ctx"

traceID := ctx.GetTraceId(c)
reqID   := ctx.GetReqId(c)
reqID   := uerrors.GetRequestID(c) // 含 X-Req-Id header key 兜底
```

非 HTTP 场景详见 [链路上下文接入指南.md](./链路上下文接入指南.md)。

### 4. 错误与 Context

```go
err := uerrors.WrapKubernetesError(ctx, k8sErr, "操作名称")
// err.RequestID 已从 ctx 自动填充
```

## 代码检查清单

- [ ] 错误使用 `uerrors.BizError` 或其包装函数
- [ ] 异步操作第一参数为 `context.Context`
- [ ] Context 正确传递，未丢失
- [ ] HTTP 服务已注册 `SetMiddleware` + `Recover` / `ExceptionHandler`
- [ ] 定时/监听入口使用 `ctx.Run`，HTTP 内异步使用 `ctx.Go`
- [ ] 日志调用传入 ctx：`logger.Infof(c, ...)`
- [ ] 移除 `gerror` / `gcode` 直接使用

## 示例

```go
func (o *nodesOperation) Top(ctx context.Context) ([]*Node, error) {
    datas, err := o.api.CoreV1().Nodes().List(ctx, v1.ListOptions{})
    if err != nil {
        return nil, uerrors.WrapKubernetesError(ctx, err, "获取节点列表")
    }
    return nodes, nil
}
```
