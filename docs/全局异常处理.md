# 全局异常处理

本文说明如何在 GoFrame 与 Gin 中接入全局异常处理，并在业务代码中通过抛错统一返回给前端。

---

## 设计约定

- HTTP 状态码固定返回 **200**
- 业务错误通过 `model/result.Response` 的 `Code` 与 `Message` 表达
- 响应头回写：`X-Trace-Id`、`X-Req-Id`、`X-Response-Time`
- 错误详情写入日志，响应体仅返回顶层 code/message
- 链路与日志接入详见 [链路上下文接入指南.md](./链路上下文接入指南.md)

---

## 目录结构

| 路径 | 说明 |
|------|------|
| `uerrors/` | `BizError` 类型、抛错辅助（`ThrowBiz`、`Must` 等）、`GetRequestID` |
| `client/request/` | `GenerateRequestID`、`ApplyHTTP` |
| `middleware/goframe/` | GoFrame 中间件，`Recover` 捕获 panic |
| `middleware/ugin/` | Gin 中间件，`ExceptionHandler` 捕获 panic |

## GoFrame

### 注册中间件

```go
import (
    "github.com/gogf/gf/v2/net/ghttp"
    mf "github.com/hosgf/element/middleware/goframe"
)

func main() {
    s := ghttp.GetServer()
    mf.SetMiddleware(s, mf.Recover)

    s.BindHandler("/demo", func(r *ghttp.Request) {
        // uerrors.ThrowValidation("name", "不能为空")
        r.Response.WriteJson(map[string]string{"ok": "true"})
    })
    s.Run()
}
```

也可单独注册：`mf.UseRecover(s)`

### 业务抛错

```go
import "github.com/hosgf/element/uerrors"

func CreateUser(name string) {
    if name == "" {
        uerrors.ThrowValidation("name", "不能为空")
    }
}

func DoQuery(ctx context.Context) {
    data, err := repo.Query(ctx)
    uerrors.Must(err, "查询失败")
}

func DoBiz() {
    uerrors.ThrowBiz(3002, "资源冲突", "唯一索引冲突")
}
```

## Gin

### 注册中间件

```go
import (
    "github.com/gin-gonic/gin"
    mu "github.com/hosgf/element/middleware/ugin"
)

func main() {
    r := gin.New()
    mu.SetMiddleware(r, mu.ExceptionHandler())

    r.GET("/demo", func(c *gin.Context) {
        c.JSON(200, gin.H{"ok": true})
    })
    _ = r.Run(":8080")
}
```

业务抛错 API 与 GoFrame 相同。

## 常用 API

| API | 说明 |
|-----|------|
| `uerrors.ThrowBiz(code, message, details...)` | 抛出业务错误 |
| `uerrors.ThrowValidation(field, message)` | 参数校验错误 |
| `uerrors.ThrowSystem(message, details...)` | 系统错误 |
| `uerrors.Must(err, message)` | err 非空则包装为系统错误并 panic |
| `uerrors.PanicIf(condition, err)` | 条件成立时 panic |
| `uerrors.GetRequestID(ctx)` | 从 ctx 读取 request_id |

---

## 自定义扩展

- GoFrame：`goframe.SetNotify(fn)` 注入 panic 通知回调
- Gin：`ugin.SetNotify(fn)` 同上
- 额外错误类型/级别可在 `uerrors/types.go` 扩展

## FAQ

**Q: 为什么 HTTP 总是 200？**

统一由业务码 `code` 表达状态，便于前端与网关统一处理。

**Q: 如何拿到请求 ID 和链路 ID？**

- 响应头：`X-Req-Id`、`X-Trace-Id`
- 日志：`<request_id>`、`{trace_id}`
- 代码：`ctx.GetReqId(c)`、`ctx.GetTraceId(c)`
